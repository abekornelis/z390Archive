I edit source with gedit on Linux, and usually PFE on Windows. PFE can handle both Unix and Windows line separators, unlike Notepad. It can be downloaded free of charge. I use Rexx as my scripting language on this project. I am using the Regina implementation on both Linux and Windows. Rexx also runs on TSO and CMS of course. I am building tools that compare files and build all or part of the project.

I tried to produce source documentation from the source code by running Javadoc. It totally failed to produce any documentation because of a single illegal source character in tz390. See /media/CRUZER2/Dev/zVSAM/RPIs.txt for details, and also email https://mail.google.com/mail/u/0/?tab=wm#search/is%3Asent+tz390+javadoc+zscii/1624e651cdba5dea . So I bodged a version of tz390 with that character taken out in order to create the documentation. It's because of bodges like that (not functionally part of the project) that I need to be able to compare source files. Otherwise I will end up with many source files with unknown changes. Update: the problem in Ubuntu is getaroundable so I've copied the macro to Ubuntu and am using it there too (with a little more tediousness).

A note on Javadoc: it extracts from source code any comments that follow a particular format. Normal Java multiline comments begin with '/*' and end with '*/'. The comments that Javadoc extracts are the subset beginning '/**'. It then looks for particular keywords within those and formats them. Much of the existing Java code has comments beginning '/**' that were probably written before Javadoc existed. That's why some of the Javadoc output large swathes of unformatted z390 commentary.
